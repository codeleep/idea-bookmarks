# 书签导入、导出与分享

适用版本：`262.11879.100.11`，官方 IDEA 2026.2.4。更新时间：2026-11-09。

## 1. 入口与格式

在 Bookmarks 工具窗口右上角原生“⋮”菜单或右键菜单打开“导入、导出与分享”；也可在 Find Action 搜索下面的动作。

| 动作 | 用途 | 包含内容 |
|---|---|---|
| 导出书签 JSON… | 完整迁移、备份、交换 | 稳定 ID、分组树、多组引用、默认组、快捷标记、完整 Markdown、提供器属性、关联类型与说明 |
| 导出书签 Markdown… | 阅读、代码导读和分享 | 分组完整路径、文件与行位置、项目相对代码链接、完整 Markdown 描述和关联摘要 |
| 导入书签 JSON… | 将 JSON 合并到或恢复到当前上下文 | 先预览变更和差异，确认后自动备份并写入 |

Markdown 是阅读文档，不能作为完整恢复文件导入。需要保留可编辑结构时，同时分享 JSON。

## 2. 导出与跨目录迁移

没有选中分组时，导出当前上下文的全部书签。选中一个或多个分组后，可以选择“选中分组及子分组”或“当前上下文全部书签”。

导出的结构按下表处理，源项目不会被修改。

| 情况 | 处理规则 |
|---|---|
| 同时选择父组和子组 | 每个分组只导出一次 |
| 只选择一个子树 | 子树顶层的父引用清空，内部层级、ID 与顺序保留 |
| 选中的不同子树根节点同名 | 在导出文件中依次追加 `(2)` 等后缀，确保新顶层名称唯一 |
| 一个书签被多个导出分组引用 | 书签和描述仅保存一份，分组保留各自引用 |
| 关联两端都在导出范围 | 保留关联 ID、类型、方向和说明 |
| 关联的另一端未导出 | 省略这条边，不创建悬空关系；描述原文中的链接仍保留 |
| 项目内文件 URL | 写为 `file://$PROJECT_DIR$/相对路径`；导入时使用目标项目目录展开 |
| VCS Log 书签的项目内仓库根目录 | 写为 `$PROJECT_DIR$` 或其相对子目录 |
| 项目外文件、未知提供器属性 | 保留原值；跨机器后不保证能导航 |

代码位置是导出时的位置，不会比较两个检出目录的提交或自动适配代码差异。建议先将目标项目切到对应 Git 分支和提交，再导入 JSON。

Markdown 中的代码链接相对项目根目录，建议将文件保存到项目根目录；行书签使用从 1 开始的 `#L行号` 锚点，能否按行跳转由阅读器决定。描述中的图片和相对链接保留原文，不复制对应资源。

## 3. 导入预览与合并规则

选择 JSON 后，预览窗口提供“变更明细”和 IDEA 原生“差异对比”。后者对比当前状态与导入后的完整 JSON，切换导入方式或冲突策略时同步更新。

默认使用合并，规则如下。

| 对象或冲突 | 合并行为 |
|---|---|
| 同一代码位置，源 ID 不同 | 复用已有书签 ID，不重复创建 |
| 同一分组完整路径，源 ID 不同 | 复用目标分组，追加缺少的书签引用 |
| ID 相同但位置或分组路径不同 | 新对象分配新 ID，保留现有对象 |
| 现有描述为空，导入描述非空 | 自动补充描述 |
| 两份描述不同且现有描述非空 | 默认保留现有描述；可统一选择“采用导入描述” |
| 导入描述为 null | 合并时不清除现有描述；完整恢复可使用替换 |
| 同位置书签的快捷标记不同 | 保留现有快捷标记 |
| 新书签的快捷标记已占用 | 新书签改为普通书签，明细中提示 |
| 已有默认分组 | 保留；目标没有默认组时才采用导入默认组 |
| 已有对象未出现在 JSON 中 | 保留；合并不会删除、改名或移动现有分组 |

关系按书签最终 ID 重映射。相同端点与类型复用已有关系；`RELATED` 反向视为同一关系。已有说明为空时自动补充，不同非空说明沿用同一个冲突策略；预览显示关联数量及内容冲突。不同关系的 ID 冲突会分配新 UUID。合并后两端相同的关系跳过并在明细提示。采用的导入描述中的 `bookmark://` 链接也跟随映射，保留的现有描述不被改写。

“替换”会用导入快照替换当前上下文，包括删除 JSON 中没有的原内容。预览会显示替换前后的数量及完整差异，确认按钮为“备份并替换”。

预览期间如果当前书签发生修改，或分支上下文已经恢复，提交会被拒绝，需要重新导入并预览。取消预览不会写入任何书签。

## 4. 备份、恢复与分支范围

每次实际导入前，原内容自动保存到项目 `.idea/bookmarks-import-backups/bookmarks-时间戳-UUID.json`。成功提示会显示完整路径；备份失败时不修改当前书签。

恢复时重新选择该备份 JSON，选择“替换”，检查差异后点击“备份并替换”。恢复本身也会备份恢复前的状态。

描述编辑是即时保存的。导入时会关闭已有的书签描述编辑页并移除旧监听器，避免旧缓冲区覆盖导入结果；导入后重新点击“编辑”即可。

操作范围是当前上下文：启用原有随分支恢复设置时，对当前 Git 分支上下文生效；关闭该设置时，对当前共用状态生效。导入不会批量改写其他分支已保存的上下文归档。原有分支保存与恢复仍使用 `BranchContextTracker → WorkingContextManager`。

## 5. JSON 与 AI 工具的关系

交换 JSON 从 `.10` 起使用 `formatVersion = 3`，保留 `bookmarks` / `groups` 和 `descriptionMarkdown`，增加 `relations` 数组；输入兼容格式 2，但格式 2 不得附带关系。原格式 2 状态首次加载后备份再升级。旧插件与仅支持格式 2 的工具不能读取格式 3。IDE 导出不附带本机 `_source` 路径、提交和校验元数据；导入可读取离线 AI 工具导出的同结构 JSON，并忽略其中 `_source`，以便导入其他项目。

`tools/bookmarks_store.py apply` 仍是关闭项目后使用的离线写回工具，保留它原有的源文件、Git 分支与提交校验。IDE 导出的可移植 JSON 不可直接替代离线工具的带 `_source` 导出：需要离线应用时，应先导出目标文件，再将业务数据合入目标导出并保留目标 `_source`。

个人阅读路线、已读进度、源码复核基线与去重完整源码快照不进入交换 JSON 或 Markdown。导入书签不会把未经复核的源码自动标为已复核。

文件输入限制为 UTF-8 JSON、10 MiB、20000 个书签、5000 个分组、50000 条关系，单条关系说明最多 10000 个 UTF-16 字符。未知格式版本、重复键、字段类型错误、悬空引用、循环层级、重复位置、重复快捷标记和项目相对路径穿越会被拒绝。自关联、悬空关系端点、重复关系 ID／端点类型及未知关系类型也会拒绝。未知提供器记录会保留，并在预览中提示；缺失目标文件与项目外文件也会提示。
