# 书签工作台、巡检与保存视图

## 1. 入口与范围

本说明对应插件 `262.11879.100.12`，适用于官方 IDEA `2026.2.4 / 262.11879.100`。

Bookmarks 工具栏固定显示新增列表、搜索、阅读工作台和编辑。巡检、导入导出、分组管理与列表显示并入工具窗口右上角原生三个点“⋮”菜单，原右键菜单和 Find Action 入口保留。阅读工作台也复用原生“⋮”菜单，并根据当前页签显示对应管理操作；内容区不再新增“更多”按钮，底部仅放常用操作。

功能入口如下，也可通过 Find Action 搜索对应名称。

| 功能 | 入口 | 操作范围 |
|---|---|---|
| 失效书签巡检与修复 | Bookmarks 工具窗口右上角原生“⋮”菜单或右键菜单 | 当前书签上下文的普通本地文件和行书签 |
| 代码阅读路线 | Bookmarks 工具栏或右键菜单，或右侧“书签阅读工作台” | 所选分组及其全部子分组 |
| 源码变更影响 | 书签右键菜单或工作台“变更影响”页 | 当前上下文普通本地文件、行书签；按完整文件比较 |
| 书签关联 | 书签右键菜单或工作台“书签关联”页 | 当前上下文中的稳定书签 ID |
| 高级筛选与保存视图 | 原有搜索按钮 | 当前书签上下文；保存视图保存在项目个人配置 |

## 2. 巡检与修复

巡检读取 IDEA 当前文档，包括尚未保存的编辑内容；后台执行，不修改源码或书签。结果显示书签 ID、文件、IDEA 显示行号、状态、原锚点、当前源码行、描述和全部所属分组。

状态含义如下。

| 状态 | 判断方式 |
|---|---|
| 正常 | 本地文件存在；行书签行号有效，提供的锚点与源码逐字相等 |
| 文件不存在 | 本地目标文件不存在或已失效 |
| 行号越界 | 行号超出当前文档范围 |
| 源码锚点不匹配 | 保留缩进、Tab、尾空白后，原锚点与当前行仍不同 |
| 无法读取文本 | 行书签目标不是可读取的文本文件 |
| 未检查 | 非本地 URL 或其他提供器，保留原数据和语义 |

选中失效项，点击“修复所选书签…”。文件存在时提供原文精确匹配、仅空白不同的候选；重复源码行会显示多个候选，最多列出 200 个，不自动选择并写入。也可选择目标文件或输入本地 URL，再通过从 **1** 开始的界面行号预览指定位置。文件书签保持文件书签类型。

预览显示新旧位置和锚点。点击“确认修复”后，再次核对候选源码，保存完整备份到 `.idea/bookmarks-import-backups/`，复用原有导入写回机制。只修改所选书签的定位属性，保留其 ID、描述、快捷标记及全部分组引用。

以下情况会拒绝修复：源码在预览后变化、书签或分支上下文变化、目标位置已经存在另一条书签、备份失败。取消预览不写入。需要恢复时，从“导入、导出与分享”导入备份并选择替换。

`lineText` 的严格匹配保护保持原样。空白相似只用于列出候选；确认后保存的是新源码行原文，存储行号仍从 **0** 开始。

## 3. 代码阅读路线

每个分组对应一条个人阅读路线，包含该组及子组的书签。初始顺序为分组先序遍历和各组已有引用顺序；共享书签按稳定 ID 去重。通过工具窗口右上角原生“⋮ → 调整顺序…”整理路线；独立窗口支持“上移一站／下移一站”和 Alt+↑／Alt+↓，点击“应用顺序”才保存。取消时保留原顺序。调整只修改阅读路线，保留当前阅读位置、最新已读进度、分组树及其原有排序；窗口打开后书签或分支变化会拒绝应用。

底部保留“上一站”“下一站”和“标为已读／标为未读”，用于阅读导航和记录进度。双击列表项或按 Enter 打开代码，也可在原生“⋮”菜单中选择“打开当前代码”。路线现在位于原生 Tool Window“书签阅读工作台”的“阅读路线”页，默认停靠在右侧。可使用 IDEA 标准工具窗口菜单调整位置、停靠或浮动，与代码编辑器同时使用。路线全文搜索沿用完整描述、分组路径、文件和锚点查询；筛选时上一站／下一站只遍历匹配结果，“调整顺序…”暂不可用。“标为已读／标为未读”记录进度，打开代码本身不自动标记已读。“⋮ → 重置进度…”经确认后清除已读状态并返回首站，保留路线排序。原有“查看变更影响”“查看关联”也放在原生“⋮”菜单中，保留带当前书签切换页签的能力。

分组改名后沿用同一条路线。移除的书签会在刷新时从路线和进度中排除，新加入的书签追加到末尾；其他步骤的顺序及进度保留。无法定位的步骤仍显示，可通过巡检修复。

阅读路线在 `workspace.xml` 的 `BookmarksWorkspace` 组件保存。启用原有随分支恢复选项时，`BookmarkContextProvider` 将 `BookmarkReadingState` 一并交给官方任务上下文存档；切换分支恢复对应路线顺序、当前步骤和已读标记。旧存档没有该元素时，恢复为空阅读进度。关闭随分支恢复后，路线随当前共用书签状态使用。

阅读路线的原生“⋮”菜单新增“源码分析”和“编辑本站说明…”。本站说明使用 IDEA 编辑组件与 Markdown 文件类型，仅属于当前分组路线中的这一步，支持记录阅读问题、下一站理由、源码／测试依据和待确认项，不改变书签的共享描述。取消不写回；保存后随原分支阅读状态恢复。一次最多 50000 字符；删除路线中的书签后清理相应说明。

## 4. 高级筛选与保存视图

查询沿用全文搜索的中文、大小写不敏感及多词 AND 规则。以下条件同时满足才会命中，共享书签只显示一次。

| 条件 | 用法 |
|---|---|
| 分组 | 选择指定分组及其子分组 |
| 目录 | 输入项目相对目录或绝对目录，按完整路径段匹配 |
| 当前文件 | 根据当前打开的源文件筛选，没有源文件时返回空结果 |
| 描述 | 不限、有描述、无描述；空白描述视为无描述 |
| 状态 | 不限、正常、失效、未检查，使用相同巡检规则 |
| 类型 | 不限、行书签、文件书签、其他提供器 |

点击“保存视图…”为条件命名；重名会拒绝覆盖。保存的是查询条件，每次选择视图时根据当前上下文重新计算。删除视图不会删除书签，“清除筛选”也不会删除保存视图。

保存视图属于项目个人配置，切换分支后仍可选择。视图引用的分组在当前分支不存在时，显示空结果和缺失分组提示，避免意外扩大查询范围。已删除视图的修改方式为重新保存；当前不提供重命名按钮。

## 5. 源码变更影响

先打开“书签阅读工作台”，在“变更影响”页选中一条或多条书签，检查源码和描述，再点击“建立基线”或“确认已复核”。首次使用显示“未建立复核基线”，插件不会静默把当前代码标为已复核。

工作台创建后监听相关文件的文档编辑与 VFS 变化，在后台延迟合并检查，包括未保存的编辑内容。文件与已复核版本不同时，标签页显示“变更影响 (N)”，阅读路线对应步骤显示警示；关闭工作台可见性不会销毁已经创建的监听器，关闭项目会释放它们。提醒显示在工作台内，不发送系统通知。

状态和操作按下表使用。

| 状态／操作 | 含义 |
|---|---|
| 已复核，源码未变化 | 当前完整文件内容与该书签的基线相同 |
| 源码已变化，待复核 | 文件任一位置变化，即使书签所在行仍精确匹配，也会提示 |
| 文件位置变化，待复核 | 相同书签 ID 指向的文件 URL 变化 |
| 文件不可用／不支持／过大 | 文件缺失、目录、其他 provider 或超出限制，不误报为已复核 |
| 查看差异 | IDEA 原生只读 Diff，比较已复核版本和当前编辑内容 |
| 建立基线／确认已复核 | 明确确认后接受当前版本，重新检查模型、分支、基线版本和文档修改戳 |
| ⋮ → 清除所选基线 | 回到未复核状态，清理不再被引用的快照，保留路线进度 |

这是**文件级提醒**，不是方法级语义分析；不会宣称具体某个方法受影响，也不自动修改描述、修复锚点或写入源码。描述自上次复核后也有修改时，详情单独提示。严格 `lineText` 导航保护继续执行，复核基线不能使失效锚点自动变为有效。

基线保存完整文本供差异查看，按 SHA-256 去重；单文件上限 512 Ki 个 UTF-16 字符，当前阅读状态的去重快照合计上限 8 Mi 个字符。超过限制会拒绝记录，现有基线保持原样。基线属于个人阅读状态，随原分支上下文保存，不进入 JSON 或 Markdown 分享。

## 6. 书签关联与内部链接

在“书签关联”页全文查找起点，点击“新建关联…”，选择目标书签、类型并填写说明。目标选择器同样支持全文查询，不需要手写 ID。允许创建以下关系。

| 类型 | 存储值 | 方向 |
|---|---|---|
| 调用 | `CALLS` | 起点到目标 |
| 实现 | `IMPLEMENTS` | 起点到目标 |
| 设计依据 | `DESIGN` | 起点到目标 |
| 相关 | `RELATED` | 双向，反向重复视为同一关系 |

每个端点都可查看全部出边和入边，列表显示 `→`、`←` 或 `↔`。双击或底部“打开代码”跳到另一端；“查看目标关联”继续沿关系浏览。在工具窗口右上角原生“⋮”或关联列表右键菜单中编辑类型和说明，编辑保留关联 ID。原生“⋮”菜单同时提供删除、查看目标关联和复制当前书签链接；底部只保留“新建关联…”和“打开代码”。删除关联只删除这条边，两端书签与分组仍保留。写入前备份完整 JSON，并拒绝对过期书签／分支快照操作。

关联连接稳定书签 ID，多个组里的同一书签共享关系。移除一个组的引用保留关系；删除最后一个引用时清理相连关系。关系图可以成环，但不允许自关联、悬空端点或同类型重复边，独立于分组树的无环约束。

“复制当前书签链接”或右键“复制书签链接”生成 `bookmark://<编码后的ID>`。描述可写 `[查看入口](bookmark://bookmark-id)`；Bookmarks 轻量预览和阅读路线点击后在当前上下文导航。目标不在当前上下文或提供器不可用时无法跳转。IDE 自带 Markdown 编辑页、外部 Markdown 阅读器不承诺识别该协议。

关联随格式 3 JSON 一起分享，Markdown 导出附带关系摘要。子树导出只包含两端都在导出范围内的关系；合并按最终 ID 重映射端点，以及采用的导入描述中的内部链接。详细规则见 [导入导出说明](IMPORT_EXPORT.md)。

## 7. 存储与二开边界

新增个人状态与书签数据分开保存。

| 数据 | 位置 | 共享与导出规则 |
|---|---|---|
| 书签、描述、分组引用、关联 | `.idea/bookmarks.xml`，格式 3 | JSON 完整导出，Markdown 含关系摘要 |
| 保存视图 | `.idea/workspace.xml` 的 `BookmarksWorkspace` | 项目个人配置，不进入书签 JSON |
| 路线顺序、进度、本站说明与源码复核基线 | 同一个人组件的 `reading` | 随分支上下文额外保存 `BookmarkReadingState`，不进入书签 JSON |
| 修复前备份 | `.idea/bookmarks-import-backups/` | 完整可移植书签 JSON，可通过现有导入恢复 |

`.10` 读取格式 2 并升级为 3；首次迁移保存 `.idea/bookmarks-format2-backup.xml`，保留原 ID、引用和描述。离线 AI 工具同步支持格式 2、3，维护书签、分组引用与关联，保留 `_source` 并遵守关闭项目、重新导出、备份及原子写回规则。编辑分支存档时应保留 `ManagerState` 之外的其他元素，包括新增的 `BookmarkReadingState`。

## 8. 验证

`tests/runtime/BookmarkWorkflowsSmoke.java` 和 `BookmarkWorkbenchSmoke.java` 使用实际安装的插件、原生文档、上下文提供器、备份写入和 XML 序列化，验证严格锚点及修复后导航、共享引用、重复候选、位置冲突、源码和模型过期、组合筛选、个人状态复制隔离、路线清理、旧上下文兼容及真实项目重启。

新增检查包括格式 3 迁移、关联合并和 ID 冲突、内部链接、安全渲染、关系删除范围、文件内容变化但锚点有效、显式复核、过期文档／上下文拦截、私有快照去重和真实项目重启。`.10` GUI 记录见 `docs/evidence/gui-workbench-validation.json`，`.11` 布局、菜单、排序确认／取消及窄面板检查见 `docs/evidence/gui-action-layout-validation.json`。

完整运行验证命令如下。

```bash
python3 tools/build.py --idea-home "$BOOKMARKS_IDEA_HOME"
python3 tools/runtime_smoke.py --idea-home "$BOOKMARKS_IDEA_HOME"
python3 -m unittest discover -s tests -p 'test_*.py'
```

源码分析与原生查询结果收录的操作、已验证范围和类图条件见 [源码阅读与原生能力](SOURCE_READING.md)。
